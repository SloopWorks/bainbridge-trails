# Bainbridge Trails — MVP scope (v1 core)

Date: 2026-10-19
Status: Tech-lead brief. Owner paused field data collection; build the core app now and expand later.
Parent spec: `2026-10-18-bainbridge-trails-design.md` (all owner decisions there still hold).

## Goal
A usable, polished app on Android + iOS (Compose Multiplatform) covering the core loop:
**see the island's trails → pick one → walk it → see progress grow → celebrate completions → compare on a public board.**

## Starting point (already built in spikes)
- Data: `trails.json` (114 named trails), `coverage_segments.json`, `trailheads.json`, PMTiles basemap/trails/terrain, 3 map styles (Topo default).
- `:coverage` (HMM map matching, per-segment tick bitsets, `Progress`, `TrailStatus`), `:tracking` (sessions, gating, `RecordingController`, Android FGS + iOS recorder, crash recovery).
- `RecordScreen` + `ResultsSheet` spike UI; no navigation, default Material theme, trail status faked in style.

## MVP screens / flows (in scope)
1. **App shell**: bottom navigation — Map · Trails · Record (center action) · Me. Leaderboard reachable from Me (and a Map/Trails entry point). Custom app theme (palette from `docs/spikes/map-render/styles.md`), light + dark.
2. **First run**: 2–3 onboarding pages (what the app does, how coverage works, privacy: tracks stay on phone). Location permission asked only at first Start (existing `PermissionFlow`).
3. **Map**: real per-trail status colors driven by the user's coverage (replace the faked style status). Tap a trail → bottom sheet preview → Trail detail. Locate-me button. Style picker (Topo/Light/Dark, Dark auto with system dark mode) in Settings.
4. **Trails list**: named trails only; search; filter by status and park; sort (name / % / length / nearest-not-needed-for-MVP). Row: name, park, length (official else computed), % + status chip.
5. **Trail detail**: mini map focused on the trail, status + %, length, elevation gain, manager/park, trailheads, official map link, community stats ("N people completed", median %) when online, "Start walk" button.
6. **Record**: existing flow, restyled; live provisional coverage during the walk (trails touched + their %); Finish → results.
7. **Results + celebration**: per-trail before/after, island %; full-screen celebration when a trail crosses completion (screen-reader text, reduced-motion variant).
8. **Me / stats**: island %, trails completed (x / 114), miles walked on trails, list of in-progress trails, walk history (date, duration, distance, trails touched — no map of raw tracks needed for MVP).
9. **Leaderboard**: public list ranked by island %, tiebreak trails completed; shows name/anon name, %, trails completed; highlights "you".
10. **Account & profile**: sign in (Google on Android, Apple on iOS; platform glue behind interfaces, config via build properties — real client IDs supplied later by owner), display name or auto-anonymous ("Mossy Heron 42"), switch any time, name blocklist, delete account (server + local option). App works fully offline/signed-out.
11. **Settings / about**: map style, units (mi/km), attribution (ODbL etc. from `data/dist/ATTRIBUTION.md`), privacy policy link placeholder, version.
12. **Sync**: per-segment coverage upload on sign-in and after each finished walk; merge server coverage down on new device. Offline queue.

## Backend (Cloudflare Workers + D1, $0)
`backend/` TypeScript Worker: verify Apple/Google ID tokens (JWKS), issue own session tokens; users, per-segment coverage (union of tick bitsets, same encoding as `CoverageState.encode`), leaderboard, per-trail community stats, display-name moderation (blocklist, report), admin removal, account deletion, plausibility limits on coverage growth. A **dev-only auth** path (enabled only by an env flag in local `wrangler dev`) so the emulator can exercise the full loop without real OAuth clients. Tests with vitest + local D1. Not deployed by agents (needs owner's Cloudflare account) — documented deploy steps instead.

## SloopWorks tooling
- **Debug drawer** (`~/workspace/debugdrawer`) in debug builds: backend switch (local `10.0.2.2:8787` / prod), logs, custom panels (dataset info, coverage reset/inject, recording state, simulate walk). Must build without the sibling checkout (noop fallback).
- **SWIP instrumentation**: product registry + codegen does not exist for bainbridge; evaluate `LOCAL_ONLY`; otherwise a thin in-app analytics facade (no collection by default; spec says "analytics: none by default") feeding drawer logs, swappable for SWIP later.
- **Shipyard Deploy**: publish the dev build of this branch to `dev-v1-mvp` when done.

## Out of scope for MVP
Trailhead geofence notifications in release, groups/friends, photos, routing, offline-download UX beyond bundled data, Play/App Store submission, real OAuth client registration, Worker deployment.

## Definition of done
Builds and unit tests green (`:coverage`, `:tracking`, `:composeApp`, backend vitest); app runs on Android emulator and iOS simulator with screenshots of each main screen; reviewer round passed with P0/P1 fixed; dev build published via Shipyard (or blocker reported); PR open against `main`.
